# Analyze OpenCanbox E2E Logs

You have been asked to analyze an E2E log file (`dump_*.log`) generated by the `canbox_e2e_logger.py` script to identify bugs or anomalies in protocol translation.

Raw dump logs typically contain 5,000–6,000+ lines filled with repetitive high-frequency CAN heartbeats and serial keep-alives. **NEVER read the raw log file directly into your context** as this consumes tens of thousands of tokens and obscures the real issues.

Follow the two-step analysis workflow below:

---

## 1. Step 1: Automated Log Triage (`tools/triage_canbox_log.py`)

**Always run the triage tool first on any dump log.** It parses the entire log in < 2 seconds and produces a compact (< 1,500 tokens) markdown diagnosis:

```bash
./tools/triage_canbox_log.py <dump_file.log>
```

### What Triage Automatically Pinpoints:
1. **Chatter & Oscillation Detector (Blinking / Twitching):**
   - Automatically detects rapid flip-flops between values (e.g. radar blinking between all-clear `0xFF` and obstacle `0x00`, or trajectory angle jumping between `00 00` and `00 01`).
   - Identifies candidate CAN frames received in the preceding 100 ms before each state.
2. **Spurious Transmissions vs OEM:**
   - Detects commands emitted by OpenCanbox that the real OEM canbox never produces.
3. **Flooding / Bus Saturation:**
   - Detects commands sent at excessive rates compared to the OEM canbox.
4. **Wire Format & Length Mismatches:**
   - Immediately flags payload length discrepancies between App and OEM.

---

## 2. Step 2: Focused Differential Analysis (`tools/diff_canbox_frames.py`)

Once the triage report identifies the suspicious Command IDs or CAN frames, use `diff_canbox_frames.py` to inspect the exact byte-by-byte differences:

```bash
./tools/diff_canbox_frames.py <dump_file.log> -c <CAN_IDS> -p <PREFIXES>
```

### PSA (Peugeot 407 / CAN2004) Examples

You can either use the convenient `--preset <name>` flag or specify exact `-c <CAN_IDS> -p <PREFIXES>`:

* **Parking Radar (AAS) Blinking, Sensor Interference, or Distance Discrepancies:**
  *(CAN2004 radar on `0x0E1`; verify no crosstalk from BSI profiles `0x260`)*
  ```bash
  ./tools/diff_canbox_frames.py dump_*.log --preset radar
  # Or explicit:
  ./tools/diff_canbox_frames.py dump_*.log -c E1 260 -p 41
  ```

* **Steering Wheel Stalk Keys (SWC) & Volume Wheel:**
  *(Stalk buttons on `0x228`, lighting/rheostat on `0x128`)*
  ```bash
  ./tools/diff_canbox_frames.py dump_*.log --preset swc
  # Or explicit:
  ./tools/diff_canbox_frames.py dump_*.log -c 228 128 -p 11 21 22
  ```

* **HVAC / Dual-Zone Climate Control:**
  *(Blower/air distribution on `0x1D0`, AC/temperatures on `0x1E3`, outside temp on `0x0F6`)*
  ```bash
  ./tools/diff_canbox_frames.py dump_*.log --preset hvac
  # Or explicit:
  ./tools/diff_canbox_frames.py dump_*.log -c 1D0 1E3 0F6 -p 31
  ```

* **Doors, Trunk, Bonnet, Handbrake & Reverse Gear:**
  *(Body state on `0x0F6`, ignition & night illumination on `0x036`)*
  ```bash
  ./tools/diff_canbox_frames.py dump_*.log --preset doors
  # Or explicit:
  ./tools/diff_canbox_frames.py dump_*.log -c 036 0F6 -p 12
  ```

* **Trip Computers (Instantaneous, Trip 1, Trip 2):**
  *(Instant on `0x221`, Trip 1 on `0x2A1`, Trip 2 on `0x261`, Speed/RPM fallback on `0x0B6`)*
  ```bash
  ./tools/diff_canbox_frames.py dump_*.log --preset trip
  # Or explicit:
  ./tools/diff_canbox_frames.py dump_*.log -c 221 261 2A1 0B6 0F6 -p 13 14 15
  ```

* **Tire Pressure Monitoring (TPMS):**
  *(Wheel pressures on `0x3A1`, discrete alarms on `0x348`, status on `0x1E1`)*
  ```bash
  ./tools/diff_canbox_frames.py dump_*.log --preset tpms
  # Or explicit:
  ./tools/diff_canbox_frames.py dump_*.log -c 3A1 348 1E1 -p 18 66
  ```

* **BSI Diagnostic Faults & Warning Alerts:**
  *(Warning journal on `0x1A1`, braking/suspension faults on `0x120`, alert block on `0x168`)*
  ```bash
  ./tools/diff_canbox_frames.py dump_*.log --preset alerts
  # Or explicit:
  ./tools/diff_canbox_frames.py dump_*.log -c 1A1 120 168 -p 42
  ```

* **Vehicle Personalization & BSI Central Settings:**
  *(Lighting/locking configuration on `0x39B`, `0x2A8`)*
  ```bash
  ./tools/diff_canbox_frames.py dump_*.log --preset bsi_config
  # Or explicit:
  ./tools/diff_canbox_frames.py dump_*.log -c 39B 2A8 -p 71 72 76 79
  ```

* **Full Summary Across All Commands (no raw dump scanning):**
  ```bash
  ./tools/diff_canbox_frames.py dump_*.log -s
  ```

* **Export Deduplicated / Compressed Log (saves 98%+ tokens):**
  ```bash
  ./tools/diff_canbox_frames.py dump_*.log --preset radar --export-compressed compressed_radar.log
  ```

## 2. Interpreting the Output

The tool outputs structured event blocks:

```text
================================================================================
EVENT #2 | Time: 1790266362.075 - 1790266362.298 (dt: +0.223s) | CMD: 0x31 (HVAC_STATUS)
--------------------------------------------------------------------------------
CAN ACTION:
  1790266362.021 | ID: 0x1E3  (DLC: 8) DATA: 11 30 12 0b 00 [20] 03 00 | Delta: Byte 5: 0x60 -> 0x20
  1790266362.297 | ID: 0x1D0  (DLC: 8) DATA: 28 00 03 [02] 00 12 0b 00 | Delta: Byte 3: 0x06 -> 0x02

CANBOX APP DIFFERENCE:
  ORIG (1790266362.075): 5a a5 0c 31 45 08 00 03 30 04 32 2a 00 00 00 [78] [94]
  APP  (1790266362.298): 5a a5 0c 31 45 08 00 03 30 04 32 2a 00 00 00 [00] [1c]

  DIFFERENCE BREAKDOWN:
    * Frame Byte 15   : ORIG=0x78 (120)  !=  APP=0x00 (  0)  [XOR: 0x78]
    * Checksum Byte   : ORIG=0x94 (148)  !=  APP=0x1C ( 28)  [XOR: 0x88]
================================================================================
```

Key points to inspect:
1. **CAN ACTION**: Highlights exact byte(s) changed in brackets `[ ]` and delta values (`Byte 3: 0x06 -> 0x02`).
2. **CANBOX APP DIFFERENCE**:
   * Differing bytes are highlighted in brackets `[ ]`.
   * Look at payload byte offsets to identify which field is wrong (e.g., outdoor temperature, fan speed, door bitmask).
3. **Discrepancy Indicators**:
   * `[NO APP RESPONSE DETECTED]`: Real OEM canbox emitted a packet, but OpenCanbox remained silent (missing trigger or unhandled CAN ID).
   * `[NO OEM CANBOX FRAME]`: OpenCanbox emitted an extra or spurious frame that the real canbox does not produce.
   * `[INVALID CS]`: Checksum calculation error.

---

## 3. Pinpoint the Translation Bug in Code

Trace the identified discrepancy back to the C codebase:
1. **CAN Frame Decoding Bug (Profile layer):** Check `src/profiles/<car_model>.c`. Did the profile parse the CAN bits correctly from the CAN action?
2. **Serial Frame Serialization Bug (Protocol layer):** Check `src/protocols/proto_<hu_type>.c` or `src/protocols/proto_<hu_type>_adapter.c`. Did the serializer map the internal state byte to the correct payload position?
3. **Trigger / Timing Bug:** Check `src/core/can_router.c` or the profile event handler. Was transmission triggered on the wrong CAN frame (e.g. waiting for `0x1D0` instead of updating on `0x1E3`)?

---

## 4. Propose the Resolution & Verify

1. Present findings clearly to the user, highlighting the exact byte differences discovered by the diff tool.
2. Provide the proposed C code fix adhering strictly to `AGENTS.md` boundaries (Pure C99, zero heap allocation, lock-free ring buffer, zero MCU leakage).
3. Verify the fix using the native test suite:
   ```bash
   ~/.platformio/penv/bin/pio test -e native_test_runner
   ```
